# Final Retrospective

## Context

This note captures the team's closing retrospective for the final repository snapshot. It is intended as a lightweight record of what improved during delivery, what the repository now demonstrates well, and what the team would tighten earlier in a future iteration.

## What Went Well

- The product evolved beyond a single practice flow into a broader learning platform with onboarding, practice, progress, discussion, and quest content.
- The repository now shows clearer workflow evidence through issue templates, PR expectations, CI, a contribution guide, and a public project board.
- The final documentation pass improved how quickly reviewers can understand the product, the architecture, and the team's delivery process.

## What We Improved Late In The Project

- stronger repository-level documentation and navigation
- explicit Definition of Done and contribution expectations
- branch protection and PR-based merging discipline
- clearer deployment and demo guidance

These improvements were especially important for making the project easier to assess from the repository alone.

## What We Would Do Earlier Next Time

- enforce consistent commit naming and author identity from the first sprint
- require every active issue to have an owner, linked PR, and updated project-board status
- keep release notes and retrospective notes current throughout the project rather than concentrating them near the end
- decide earlier which repo-level artifacts are part of the assessment evidence so they are not backfilled under time pressure

## Process Evidence Now Present In The Repository

- planning and role artifacts under [`../planning`](../planning), [`../PO_work`](../PO_work), and this folder
- PR and issue templates under [`../../.github`](../../.github)
- contribution workflow in [`../../CONTRIBUTING.md`](../../CONTRIBUTING.md)
- product and engineering documentation under [`../../english-learn/docs`](../../english-learn/docs)

## Remaining Limitations

- some contribution history still reflects mixed author naming and late process cleanup
- final repository polish improved the evidence trail, but parts of the workflow would have been stronger if applied consistently from sprint one
- optional integrations still depend on local or deployment environment setup

## Closing Note

The team finished with a stronger repository than it started with: not only more product capability, but also clearer proof of planning, execution, quality checks, and reflection. That combination is what this retrospective is intended to preserve.
